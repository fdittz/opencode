## Resolution

root_cause: The OpenCode upstream code (`origin/dev`) intentionally blocks subagents from spawning sub-subagents by adding `{permission:"task", pattern:"*", action:"deny"}` to the session permission when creating subagent sessions (unless the agent explicitly has `task` in its permission config). This rule gets persisted in the SQLite database. The user's `subs` commit (`a94a3a410`) correctly removed this restriction, but OLD sessions created before the fix still have `task: deny` persisted in the DB.

fix: Already applied by commit `a94a3a410` (subs). The code that added `task: deny`, `todowrite: deny`, `todoread: deny` to subagent session permissions was removed. For old sessions with persisted `task: deny`, adding `task: true` to the GSD agent frontmatter `tools:` section would also work as a fix (since it would add `task: allow` AFTER the session's `task: deny` in the merged ruleset).

verification: Ran debug-perms.ts which confirmed agent permissions are correct. Confirmed via DB query that new sessions have `permission: "[]"`. Code at HEAD does not contain the deny-generating logic.
