<objective>
Test the Copilot auth plugin fetch interceptor body-based detection logic (`copilot.ts:63-139`).

Purpose: The fetch interceptor is the first mechanism that sets `x-initiator` header. It parses the request body to detect whether the request is agent-initiated (tool continuations where last message is NOT from user) or user-initiated. This was identified as a "fragile area" in codebase concerns, and HARD-01 requires dedicated tests. The interceptor handles three API formats (completions, responses, messages) and also detects vision requests.

Output: A test file covering all body-based detection paths, header construction, and the critical `init?.headers` spread that allows `chat.headers` hook to override values.
</objective>

  <action>
Create a test file that directly tests the `fetch` function returned by `CopilotAuthPlugin`'s `auth.loader`.

**Setup approach:** The `CopilotAuthPlugin` function returns a `Hooks` object where `hooks.auth.loader(getAuth, provider)` returns an object containing a `fetch(request, init)` function. To test in isolation:

1. Call `CopilotAuthPlugin({...})` to get hooks
2. Call `hooks.auth.loader(mockGetAuth, mockProvider)` where `mockGetAuth` returns `{ type: "oauth", refresh: "test-token" }`
3. Mock global `fetch` to capture the actual `fetch(request, init)` call and inspect the headers passed
4. Call the returned `fetch` function with various request bodies

**Test cases for isAgent detection (completions API — `body.messages` + URL includes "completions"):**

- `x-initiator: user` when last message has `role: "user"` (fresh user prompt)
- `x-initiator: agent` when last message has `role: "assistant"` (tool continuation)
- `x-initiator: agent` when last message has `role: "tool"` (tool result)

**Test cases for isAgent detection (responses API — `body.input`):**

- `x-initiator: user` when last input item has `role: "user"`
- `x-initiator: agent` when last input item has `role: "assistant"`

**Test cases for isAgent detection (messages API — `body.messages` without "completions" in URL):**

- `x-initiator: user` when last message has `role: "user"` with non-tool_result content parts
- `x-initiator: agent` when last message has `role: "user"` but ALL content parts are `type: "tool_result"`

**Test cases for isVision detection:**

- `Copilot-Vision-Request: true` when completions messages contain `image_url` parts
- `Copilot-Vision-Request: true` when responses input contains `input_image` parts
- `Copilot-Vision-Request: true` when messages API messages contain `image` parts
- No vision header when no image parts

**Test cases for header construction:**

- `Authorization: Bearer {refresh}` is set from auth info
- `User-Agent` includes `opencode/` prefix
- `Openai-Intent: conversation-edits` is always set
- `x-api-key` header is deleted (not present in final headers)
- lowercase `authorization` header is deleted (not present in final headers)
- `init?.headers` spread AFTER `x-initiator` — meaning if `init.headers` contains `x-initiator: agent`, it overrides the body-based value

**Test case for error handling:**

- Invalid/unparseable body gracefully defaults to `isAgent: false, isVision: false`

**Important conventions to follow:**

- Use `import { describe, test, expect, mock } from "bun:test"`
- Do NOT use `any` type — use typed mocks
- Follow the project's testing patterns from existing plugin tests (see `codex.test.ts`, `auth-override.test.ts`)
- The `CopilotAuthPlugin` requires a `PluginInput` parameter — examine the `@opencode-ai/plugin` types to construct a minimal valid input
- Mock `Installation.VERSION` if needed, or just expect the header to start with `opencode/`
- Use `mock()` from bun:test to create a mock for global fetch that captures calls
- Since `CopilotAuthPlugin` is async and `auth.loader` is async, await them properly
