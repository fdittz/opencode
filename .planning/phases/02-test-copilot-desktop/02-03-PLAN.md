Test the end-to-end header propagation chain: `chat.headers` hook → `LLM.stream()` headers → fetch interceptor `init.headers` spread.

Purpose: The critical insight from Phase 1 is that the fix works because of header ORDERING: the fetch interceptor sets `x-initiator` BEFORE `...(init?.headers)` spread (copilot.ts:122-123), so `chat.headers`'s `x-initiator: agent` overrides the body-based value. This plan tests that the integration between the two mechanisms works correctly — that the header propagation chain is not broken.

Output: An integration test that verifies the header override mechanism works for both subagent and regular sessions.
</objective>

  <action>
Create an integration test file that verifies the header override chain between `chat.headers` hook and the fetch interceptor.

**What this tests:** The critical mechanism that makes the Phase 1 fix work:

1. Fetch interceptor (copilot.ts:121-123):

```typescript
const headers = {
  "x-initiator": isAgent ? "agent" : "user",  // body-based value
  ...(init?.headers as Record<string, string>), // chat.headers override
  ...
}
```

2. LLM.stream() (llm.ts:208-222):

```typescript
headers: {
  ...otherHeaders,
  ...headers,  // <-- headers from chat.headers hook spread LAST
}
```

The test should verify that the spread order is correct.

**Approach:** Test the fetch interceptor's header override behavior by calling the `fetch` function with:

- Body that would make `isAgent: false` (last message is `role: "user"`)
- `init.headers` that include `x-initiator: agent` (as chat.headers would set)
- Verify that the final fetch call has `x-initiator: agent` (override wins)

And the inverse:

- Body that would make `isAgent: true` (last message is `role: "assistant"`)
- `init.headers` that include `x-initiator: user` (hypothetical override)
- Verify that the final fetch call has `x-initiator: user` (override still wins)

And the no-override case:

- Body that would make `isAgent: false` (user message)
- `init.headers` that do NOT include `x-initiator`
- Verify that the final fetch call has `x-initiator: user` (body-based value preserved)

**Test cases:**

1. **chat.headers override beats body-based detection**
   - Body has last message role: "user" → body-based isAgent: false → would set x-initiator: user
   - init.headers has x-initiator: agent (set by chat.headers for subagent)
   - Final headers should have x-initiator: agent (override wins)

2. **No override → body-based detection preserved**
   - Body has last message role: "user" → body-based isAgent: false → sets x-initiator: user
   - init.headers does NOT have x-initiator
   - Final headers should have x-initiator: user

3. **Body-based agent + no override → agent preserved**
   - Body has last message role: "assistant" → body-based isAgent: true → sets x-initiator: agent
   - init.headers does NOT have x-initiator
   - Final headers should have x-initiator: agent

4. **Complete subagent scenario: fresh task prompt with override**
   - Body has messages: [system, user] where user has the task prompt (role: "user") → isAgent: false
   - init.headers has x-initiator: agent (exactly what chat.headers sets for subagent sessions)
   - Final headers should have x-initiator: agent
   - This is THE scenario that was broken in Desktop before Phase 1 fix

**Setup:** Reuse the mock approach from Plan 01 — get the fetch function from CopilotAuthPlugin loader, mock global fetch to capture headers.

**Conventions:**

- Use same setup approach as Plan 01 tests
- Focus on the ORDERING of headers, which is the critical integration point
- Keep tests focused — don't re-test individual detection logic (that's Plan 01)
