  <files>packages/opencode/src/plugin/copilot.ts, packages/opencode/src/session/llm.ts</files>
  <action>
Investigate the two mechanisms that set `x-initiator` header for Copilot API requests and find why Desktop subagents don't get `x-initiator: agent`:

**Mechanism 1 — Fetch interceptor (copilot.ts:63-139):**
The `auth.loader` returns a custom `fetch()` that parses request body to detect `isAgent`. For Completions API: `isAgent = last.role !== "user"`. For a fresh subagent session, the last message is the user's task prompt (`role: "user"`), so body-based detection yields `isAgent: false` → `x-initiator: user`.

The interceptor builds headers with the body-based value FIRST, then spreads `init?.headers` which should override it. Verify this spread actually works by:

1. Adding temporary `console.log` / `Log.info` in the fetch interceptor to log `isAgent`, `init?.headers?.["x-initiator"]`, and final `headers["x-initiator"]` for ALL Copilot API requests
2. Run a subagent in CLI mode and capture the logs
3. If possible, run in Desktop mode and compare

**Mechanism 2 — chat.headers hook (copilot.ts:304-325):**
This hook checks `session.data.parentID` via `sdk.session.get()`. If `parentID` exists, sets `output.headers["x-initiator"] = "agent"`.

Key suspect: The `.catch(() => undefined)` on line 321 silently swallows ALL errors. If `sdk.session.get()` fails (wrong directory, timing issue, server not ready), the hook returns without setting the header.

Investigate:

1. Add logging BEFORE and AFTER the `sdk.session.get()` call to see if it succeeds
2. Log the `incoming.sessionID` and `input.directory` values
3. Check if `input.directory` (captured at plugin init time) matches the actual session's directory

**Mechanism 3 — Header propagation through AI SDK:**
The `chat.headers` output goes to `streamText()` as `headers` (llm.ts:208-223). AI SDK passes these to the provider model which calls `combineHeaders(this.config.headers(), options.headers)` before calling fetch. Verify the `x-initiator` from `chat.headers` actually arrives in `init?.headers` inside the fetch interceptor.

**What to look for:**

- Does `sdk.session.get()` succeed for subagent sessions in Desktop?
- Does `init?.headers` in the fetch interceptor contain `x-initiator: agent`?
- Is there a header casing issue (e.g., `X-Initiator` vs `x-initiator`)?
- Does the `combineHeaders` function from `@ai-sdk/provider-utils` preserve the header?

Document findings as comments in the code and record the root cause.

<task type="auto">
  <name>Task 2: Fix x-initiator header for subagent sessions</name>
  <files>packages/opencode/src/plugin/copilot.ts</files>
  <action>
Based on the investigation findings, apply the fix. The most likely scenarios and their fixes:

**Scenario A: `sdk.session.get()` fails silently in `chat.headers` hook**
Fix: Make the hook more resilient. Instead of relying on `sdk.session.get()` (which does an HTTP round-trip through the SDK client), access the session data directly via the `Session` module import. The hook receives `incoming.sessionID` — use `Session.get(incoming.sessionID)` directly instead of going through the SDK HTTP client. This eliminates potential issues with the SDK client's baseUrl, directory parameter, or fetch interception.

```typescript
// Replace sdk.session.get() with direct Session access
import { Session } from "../session"

// In chat.headers hook:
const session = await Session.get(incoming.sessionID).catch(() => undefined)
if (!session || !session.parentID) return
output.headers["x-initiator"] = "agent"
```

**Scenario B: `init?.headers` spread doesn't include `x-initiator` from `chat.headers`**
Fix: The fetch interceptor should check `init?.headers?.["x-initiator"]` before computing its own. If the header is already set by `chat.headers`, respect it:

```typescript
const initiatorFromHeaders = (init?.headers as Record<string, string>)?.["x-initiator"]
const headers: Record<string, string> = {
  "x-initiator": initiatorFromHeaders ?? (isAgent ? "agent" : "user"),
  ...(init?.headers as Record<string, string>),
  // ... rest
}
```

**Scenario C: Header casing mismatch**
Fix: Normalize header name casing when reading from `init?.headers`.
